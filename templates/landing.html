Architecture

Built as a pipeline,
not a black box.

Four stages, each auditable on its own. Nothing happens between them that a reviewer can't see.

01
Transaction ingested
Arrives with user ID, amount, device, and timestamp — nothing else.
02
5 rules evaluated
Amount spike, velocity, device, odd-hour, and round-amount checks. All visible in code.
03
Risk scored 0–5
Below 2 passes through silently. 2 and above gets queued for a human to look at.
04
Claude explains it
Plain-English rationale for the analyst. Claude never scores or blocks — the rules already did.
Why rules, not a model

The score should never
be a mystery.

Four decisions that shaped Verax, and why each one holds up under scrutiny.

A real, recurring cost
Payment fraud isn't a toy problem picked for a demo. Any platform that moves money deals with it every day.
Nothing runs unseen
A structured Flask app and a rule engine you can read top to bottom in five minutes. No hidden weights, no dead code.
AI explains, rules decide
The language model writes the rationale for a reviewer. It never scores, flags, or blocks a transaction on its own.
Limitations, stated plainly
One false negative on the labeled test set — a slow-burn pattern the current rules miss — shown in Analytics, not hidden.
